# 研究深度定义

> Research Agent 应该追求的研究深度标准

**版本**: v2.0 | **日期**: 2026-08-14

## 研究深度层次

### Level 0: 第一性原理

**问题**: XXX 的本质是什么？为什么要 XXX？

**方法**: 追问"为什么"直到无法再追问

**判断标准**:
- 是否理解根本原因？
- 能否回答"为什么要这样设计"？
- 是否触及问题的本质？

**示例**:
```
问题：为什么要使用文档化交互？

Level 0 回答：
- 因为 Agent 需要异步协作
- 因为需要可追溯性
- 因为需要可自动化
→ 本质：解决 Agent 协作的同步阻塞问题
```

---

### Level 1: 理论框架

**问题**: XXX 如何建模？决策模型是什么？

**方法**: 构建模型、形式化表达、逻辑推演

**判断标准**:
- 是否建立了理论模型？
- 能否指导具体设计？
- 逻辑是否自洽？

**示例**:
```
问题：文档化交互如何建模？

Level 1 回答：
- Agent 作为生产者/消费者
- 文档作为消息队列
- 文档状态作为交互协议
→ 模型：生产者-文档-消费者模型
```

---

### Level 2: 设计原则

**问题**: 应该遵循什么原则？原则如何权衡？

**方法**: 从理论推导原则

**判断标准**:
- 是否明确了设计原则？
- 能否指导具体方案选择？
- 原则之间是否有优先级？

**示例**:
```
问题：文档化交互应该遵循什么原则？

Level 2 回答：
- 分层原则：Level 0/1/2 按需加载
- 单向依赖原则：避免循环依赖
- 明确归属原则：每个文件有明确责任人
→ 原则：Context 最小化原则
```

---

### Level 3: 实现思路

**问题**: 如何设计？有哪些方案？

**方法**: 从原则推导思路

**判断标准**:
- 是否提供了清晰的实现路径？
- 是否考虑了多种方案对比？
- 是否明确了权衡点？

---

### Level 4: 具体实现 ❌

**问题**: 代码怎么写？配置放哪里？

**方法**: **这不是 Research Agent 的职责范围**

**判断标准**:
- Research Agent 不应该停留在 Level 4
- 应该由执行层 Agent 完成
- Research Agent 只提供 Level 0-3 的深度

---

## Research Agent 的目标深度

### 标准要求

```
最小深度：Level 1（理论框架）
标准深度：Level 2（设计原则）
优秀深度：Level 0-2 全覆盖
```

### 深度检查

**每次研究后自问**：
- [ ] 我是否理解了"为什么"？（Level 0）
- [ ] 我是否建立了理论模型？（Level 1）
- [ ] 我是否明确了设计原则？（Level 2）
- [ ] 我是否提供了实现思路？（Level 3）
- [ ] 我是否陷入了实施细节？（Level 4 ❌）

## 深度提升技巧

### 技巧 1: 持续追问

```
陈述：需要质量门控
追问：为什么需要？→ 因为需要判断何时呼叫 Human
追问：为什么需要判断？→ 因为要平衡自主性和控制
追问：为什么需要平衡？→ 这是 Agent 系统的本质需求
→ Level 0 达成
```

### 技巧 2: 建模思维

```
观察：质量门控包含确定性、可接受性、混淆判断
建模：三维评估模型
形式化：IF ... THEN ... ELSE ...
→ Level 1 达成
```

### 技巧 3: 原则提取

```
观察：质量门控在不同场景下表现不同
提取：PM 自主性优先原则
应用：在确定性 HIGH 时 PM 自主决策
→ Level 2 达成
```

### 技巧 4: 方案对比

```
问题：如何实现质量门控？
对比：
- 方案 A：硬编码在 AGENTS.md
- 方案 B：提取为 Skills
- 方案 C：动态配置
权衡：Token 效率 vs 灵活性
→ Level 3 达成
```
