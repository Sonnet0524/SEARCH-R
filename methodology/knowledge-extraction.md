# 知识萃取协议

> 从研究产出中提取可复用知识的方法

---

## 定位

知识萃取是**独立于 SEARCH-R 研究循环**的能力。

- SEARCH-R 的产出是研究结论，不是 Insight
- 研究过程中**可能**产生 Insight，但这是副产品
- 知识萃取是在研究产出后，**可选地**进行的知识整理动作

**关键原则**：不是每次研究都会产生 Insight。强制从研究中"榨取"洞见是过度设计。

---

## 三层知识结构

```
Info（信息）→ 事实、数据点、观察记录
  ↓ 整理后
Data（数据）→ 结构化的、可分析的信息
  ↓ 提炼后
Insight（洞见）→ 能改变行动逻辑的发现
```

### Info（信息）
- 原始事实、数据点
- 观察记录、访谈笔记
- 未经加工的素材

### Data（数据）
- 经过整理的结构化信息
- 可分析、可比较的数据集
- 分类归纳后的发现

### Insight（洞见）
- **唯一判据**：能否改变行动逻辑？
- 如果能改变 → Insight
- 如果不能 → 停留在 Info/Data 层

---

## 什么不是 Insight

- ❌ 数据点："X 的值是 Y"
- ❌ 过程结论："我们决定用方案 A"
- ❌ 工程设计："系统应该这样实现"（未上升到方法论）
- ❌ 通识："AI 正在改变世界"

---

## 萃取时机

| 场景 | 说明 |
|------|------|
| 研究产出后 | 判断是否有可提取的 Insight |
| 课题回顾时 | 梳理已有知识，发现遗漏 |
| 跨课题比较时 | 发现关联洞见 |
| 网络梳理时 | 定期巡检（每 1-2 周） |

---

## 萃取流程

```
1. 研究产出完成
    ↓
2. 判断是否有可提取的知识
    ├─ 无 → 结束（正常，不是每次都有 Insight）
    └─ 有 → 继续
    ↓
3. 三层分类：Info / Data / Insight
    ↓
4. 对 Insight 候选进行判定
    ├─ 通过"能否改变行动逻辑" → 正式记录为 Insight
    └─ 不通过 → 降级为 Data 或 Info
    ↓
5. 写入洞察索引
    ↓
6. 检查跨课题关联
    ↓
7. 更新知识图谱
```

---

## 洞察索引

维护一个索引文件，记录所有已识别的 Insight：

```markdown
## 洞察索引

### INS-001: [标题]
- 来源：[课题名/研究产出]
- 日期：YYYY-MM-DD
- 内容：[一句话描述]
- 行动影响：[如何改变行动逻辑]
- 关联课题：[相关课题列表]
```

---

## 跨课题关联

当 Insight 产生时，检查是否与其他课题相关：

- 这个 Insight 对其他课题有启发吗？
- 其他课题的研究能为这个 Insight 提供补充吗？
- 是否存在跨课题的模式或原则？
