# 课题网络梳理机制

> 定期对全部课题进行网络化梳理，发现跨课题连接

**版本**: v2.0 | **日期**: 2026-08-14

---

## 为什么需要课题网络梳理？

### 问题

当 Agent 管理多个研究课题时，常见的困境：
- 每个课题都在推进，但课题之间各自为战
- 课题 A 的发现和课题 B 的发现明明有关联，但没人注意到
- 某些课题长期没有进展，成为"僵尸课题"
- 某些课题产出了大量 Insight，但从未和其他课题产生连接

### 根因

v1.x 的课题管理是"独立管理模式"——每个课题有自己的目录、状态、进展，但课题之间没有显式的关系管理。

### 方案

课题网络梳理机制——每 1-2 周对全部课题进行一次网络化梳理：
1. 画出课题之间的连接
2. 发现跨域洞察
3. 评估课题健康度
4. 生成网络图和梳理报告

---

## 梳理频率

| 情况 | 频率 | 说明 |
|------|------|------|
| 常规梳理 | 每 1-2 周 | 标准频率 |
| 高密度期 | 每周 | 多个课题同时活跃时 |
| 低密度期 | 每 2-3 周 | 只有 1 个活跃课题时 |
| 触发式 | 随时 | Harvest 阶段发现重大跨课题关联时 |

---

## 梳理流程

### 步骤 1：全量扫描

**做什么**：读取所有课题的状态

```
1. 读取课题总览表
   → 获取所有课题列表
   → 获取每个课题的状态（active/paused/completed）

2. 读取每个活跃和暂停课题的 topic.md
   → 获取当前阶段
   → 获取最新进展
   → 获取已产出的 Insight 列表

3. 读取洞察索引
   → 获取所有 Insight 及其关联关系
```

### 步骤 2：关系分析

**做什么**：分析课题之间的连接

```
对每个 Insight，检查：
1. 它的来源课题是什么？
2. 它关联了哪些其他 Insight？
3. 这些关联 Insight 属于哪些课题？
4. 是否建立了跨课题连接？
```

**关系类型**：

| 类型 | 说明 | 标注方式 |
|------|------|----------|
| **直接关联** | 两个课题的 Insight 直接关联 | 实线连接 |
| **间接关联** | 通过第三方 Insight 间接连接 | 虚线连接 |
| **域关联** | 属于同一研究领域 | 域标签 |
| **方法关联** | 使用了相同的研究方法 | 方法标签 |

### 步骤 3：跨域洞察提炼

**做什么**：从课题交叉点发现新 Insight

```
课题 A 的 Insight #5: "Agent 的记忆应分层"
课题 B 的 Insight #8: "信息过载是效率杀手"
  ↓
发现连接：
→ 记忆分层是解决信息过载的具体策略
→ 但分层本身也会引入"层间同步"的新问题
  ↓
跨域洞察：
→ "分层架构的核心挑战不在分层本身，
   而在层间的同步策略。"
```

**跨域洞察的判定**：
- 同样使用"能否改变行动逻辑"作为唯一判据
- 跨域洞察往往比单课题洞察更有价值，因为它连接了不同领域

### 步骤 4：课题健康度评估

**做什么**：评估每个课题的健康状态

**健康度维度**：

| 维度 | 评估标准 | 健康 | 警告 |
|------|----------|------|------|
| **活跃度** | 最近一次研究时间 | ≤ 2 周 | > 4 周 |
| **深度** | 研究深度层级 | Level 1+ | Level 0 |
| **连接度** | 与其他课题的连接数 | ≥ 1 | 0（孤岛） |
| **产出度** | Insight 产出数量 | ≥ 2 | 0 |
| **方向清晰度** | 下一步是否明确 | 明确 | 模糊 |

**健康度综合评估**：

```
🟢 健康：4-5 个维度达标
🟡 注意：2-3 个维度达标
🔴 警告：0-1 个维度达标
```

### 步骤 5：生成网络图

**做什么**：可视化课题间关系

**网络图格式**（文本版）：

```
# 课题网络图 YYYY-MM-DD

## 课题节点

[课题 A] 🟢 健康 | Insight: 5 | 连接: 3
  └── Insight #001, #003, #005, #012, #015

[课题 B] 🟡 注意 | Insight: 2 | 连接: 1
  └── Insight #007, #008

[课题 C] 🔴 警告 | Insight: 0 | 连接: 0
  └── 无产出

## 课题连接

[课题 A] ──补充──→ [课题 B]
  └── Insight #015 补充了 Insight #008

[课题 A] ──衍生──→ [课题 C]
  └── Insight #012 引发了课题 C 的研究问题

## 跨域洞察

- 从 A+B 交叉点：[跨域洞察描述]

## 健康度总览

| 课题 | 活跃度 | 深度 | 连接度 | 产出度 | 方向 | 综合 |
|------|--------|------|--------|--------|------|------|
| A    | ✅     | ✅   | ✅     | ✅     | ✅   | 🟢   |
| B    | ✅     | ✅   | 🟡     | 🟡     | ✅   | 🟡   |
| C    | 🔴     | 🔴   | 🔴     | 🔴     | 🟡   | 🔴   |

## 建议行动

1. 课题 C 连接度为零，建议重点关注
2. A 和 B 的跨域洞察值得深入研究
3. 课题 B 的连接度需要提升
```

### 步骤 6：触发更新

**做什么**：根据梳理结果采取行动

| 发现 | 行动 |
|------|------|
| 新跨课题连接 | 更新相关课题的关联记录 |
| 跨域洞察 | 创建新的 Insight 候选 |
| 课题健康度 🔴 | 标记为需关注，建议 Human 决策 |
| 矛盾 Insight | 触发冲突解决流程 |
| 孤岛课题 | 建议建立连接或考虑归档 |

## 课题网络图的演进

### 初始状态

```
[课题 A]          [课题 B]          [课题 C]
 (孤岛)            (孤岛)            (孤岛)
```

### 第一次连接

```
[课题 A] ───→ [课题 B]
              Insight #5 补充 #8

[课题 C]
 (仍孤岛)
```

### 网络形成

```
[课题 A] ───→ [课题 B]
   │              │
   │              │
   ↓              ↓
[课题 C] ←─── [课题 D]

A→B: 补充    A→C: 衍生
B→D: 增强    C→D: 方法关联
```

### 枢纽节点识别

当某个课题的连接数显著高于其他课题时，它成为"枢纽节点"——这个课题的 Insight 对整个知识网络影响最大。

```
枢纽节点的价值：
1. 优先投入研究资源
2. 枢纽的 Insight 产出会影响多个课题
3. 枢纽退化会影响整个网络
```

## 实践指南

### 梳理的最佳时机

| 时机 | 说明 |
|------|------|
| 固定周期 | 每 1-2 周的固定时间 |
| Harvest 后 | 重大研究产出后 |
| 新课题启动前 | 检查现有网络，避免重复 |
| 课题归档前 | 确保关联已记录 |

### 梳理需要多长时间？

- 3 个课题：约 15-20 分钟
- 5-7 个课题：约 30-40 分钟
- 10+ 个课题：约 45-60 分钟

### 常见问题

**Q: 梳理频率太高会不会浪费时间？**
A: 不会。梳理是"站在高处看全局"，往往能发现低头研究时看不到的连接。15 分钟的梳理可能省掉 2 小时的重复研究。

**Q: 只有 1 个课题时需要梳理吗？**
A: 不需要网络梳理（没有网络可言），但仍可以做"课题健康度自检"。

**Q: 梳理结果放在哪里？**
A: 梳理报告放在 `reflections/` 目录，网络图可以放在课题总览表或单独文件。
