# SEARCH-R 循环详解（v2.0 增强版）

> 研究型 Agent 的标准工作循环，v2.0 增加知识交互协议

**版本**: v2.0 | **日期**: 2026-08-14

---

## 方法论概述

SEARCH-R 是一个**研究循环方法论**，指导研究型 Agent 系统化地进行研究工作。

### 命名由来

**Search（搜索）+ Reflect（反思）= 持续探索真理**

### v2.0 关键变化

v1.x 的 SEARCH-R 循环是一个**研究流程框架**——告诉 Agent "先做什么、后做什么"。

v2.0 的 SEARCH-R 循环升级为**知识操作系统**——不仅定义流程，还定义每个阶段如何与知识体系交互。

```
v1.x: S → E → A → R → C → H → R（做什么）
v2.0: S → E → A → R → C → H → R（做什么 + 知识怎么流动）
```

---

## SEARCH-R 循环总览

```
S - Survey（观察调研）    → 发现问题 + 检索已有知识
E - Explore（探索检索）   → 检索外部知识 + 萃取新信息
A - Analyze（分析思考）   → 理论构建 + Data→Insight 提炼
R - Review（评审探讨）    → Human 评审 + Insight 验证
C - Confirm（确认验证）   → 实践验证 + Insight 检验
H - Harvest（收获产出）   → 沉淀成果 + 归档 Insight + 跨课题关联
R - Reflect（反思迭代）   → 反思优化 + 课题网络影响评估

循环：S → E → A → R → C → H → R → (回到S)
```

---

## 各阶段详解（v2.0 增强版）

### S - Survey（观察调研）

**目标**：从实践中发现问题和模式

**v1.x 内容**：
- 观察实践过程
- 识别关键现象
- 发现潜在问题
- 记录观察笔记

**v2.0 新增 — 知识交互协议**：

| 动作 | 说明 | 示例 |
|------|------|------|
| **检索已有知识** | 在开始新研究前，先检查已有知识库是否已有相关 Insight | "关于 Agent 协作，我们之前已经产出了什么 Insight？" |
| **避免重复研究** | 如果已有 Insight 覆盖了当前问题，直接复用而非重新研究 | "之前的 Insight #12 已经回答了这个问题，直接引用" |
| **标记知识缺口** | 明确哪些问题在已有知识中找不到答案 | "关于记忆压缩，我们没有现成的 Insight，需要从头研究" |

**知识萃取动作**：
- 识别新出现的 Info（信息）
- 记录到 observations/ 并标记为 Info 级别

**输入**：
- 项目背景和上下文
- 实践观察资料
- 已有知识库（insights_index.md）

**输出**：
- 观察笔记（observations/）
- 问题清单
- 知识缺口清单
- 待探索方向

**质量门控**：
- 是否发现有意义的问题？
- 是否检查了已有知识？
- 问题是否值得研究？

---

### E - Explore（探索检索）

**目标**：检索相关知识和现有研究

**v1.x 内容**：
- 文献检索
- 技术调研
- 案例分析
- 知识整理

**v2.0 新增 — 知识交互协议**：

| 动作 | 说明 | 示例 |
|------|------|------|
| **萃取新信息** | 从检索结果中识别新的 Info（信息） | "这篇论文提到了一个我们没有的概念 X" |
| **结构化整理** | 将 Info 整理为 Data（数据），使其可分析 | "把这 5 个 Info 整理成对比表格" |
| **跨课题关联检查** | 检索到的知识是否与已有课题相关？ | "这个发现对另一个课题的 Insight #5 有补充作用" |

**知识萃取动作**：
- 从检索结果中萃取 Info
- 将 Info 整理为 Data
- 检查跨课题关联

**输入**：
- Survey 阶段发现的问题
- 检索关键词
- 知识源列表
- 已有知识库

**输出**：
- 检索报告（retrievals/）
- 整理后的 Data
- 知识关联标注

**质量门控**：
- 是否找到足够的相关知识？
- 检索结果是否已整理为 Data？
- 是否检查了跨课题关联？

---

### A - Analyze（分析思考）

**目标**：深度理论构建和分析

**v1.x 内容**：
- 理论构建
- 模式识别
- 假设提出
- 逻辑推演

**v2.0 新增 — 知识交互协议**：

| 动作 | 说明 | 示例 |
|------|------|------|
| **Data→Insight 提炼** | 从 Data 中提炼出能改变行动逻辑的 Insight | "从 10 个案例中提炼出一条设计原则" |
| **Insight 判定** | 用唯一判据检验：能否改变行动逻辑？ | "这个结论能改变我们的下一步行动吗？能 → Insight" |
| **不合格洞见过滤** | 把不是 Insight 的发现降级 | "这只是数据点，不是 Insight，标记为 Data" |

**知识萃取动作**：
- **核心动作**：Data → Insight 提炼
- 用"能否改变行动逻辑"判定洞见
- 过滤不合格洞见

**输入**：
- 观察笔记
- 检索报告
- 整理后的 Data
- 现有理论

**输出**：
- 理论文档（theory/）
- 提炼出的 Insight（候选）
- 概念模型
- 设计原则

**质量门控**：
- 理论是否逻辑自洽？
- Insight 是否通过唯一判据？
- 是否达到 Level 0-2 深度？

---

### R - Review（评审探讨）

**目标**：Human 参与评审和探讨

**v1.x 内容**：
- Human 评审理论
- 深入探讨
- 方向调整
- 决策确认

**v2.0 新增 — 知识交互协议**：

| 动作 | 说明 | 示例 |
|------|------|------|
| **Insight 验证** | 让 Human 验证 Insight 是否真的能改变行动逻辑 | "你觉得这条设计原则是否站得住脚？" |
| **关联发现** | Human 可能从不同角度发现新关联 | "Human 提到这个 Insight 和 Y 领域的问题类似" |
| **Insight 修订** | 根据 Human 反馈修订 Insight | "把 Insight #7 的适用范围从 A 缩小到 A 的子集" |

**输入**：
- 理论文档
- 候选 Insight
- 设计方案
- 待确认问题

**输出**：
- 评审记录
- 修订后的 Insight
- 决策文档
- 改进建议

**质量门控**：
- Human 是否认可 Insight？
- Insight 是否经得起推敲？
- 是否需要调整研究方向？

---

### C - Confirm（确认验证）

**目标**：在实践中验证理论

**v1.x 内容**：
- 设计验证实验
- 实施验证
- 收集数据
- 分析结果

**v2.0 新增 — 知识交互协议**：

| 动作 | 说明 | 示例 |
|------|------|------|
| **Insight 实践检验** | 将 Insight 应用到实际场景，看是否真的改变行动逻辑 | "按这条原则做，效果确实更好吗？" |
| **反例收集** | 有意寻找反例，测试 Insight 的边界 | "有没有例外情况？边界在哪？" |
| **Insight 定级** | 验证通过的 Insight 正式定级 | "Insight #7 验证通过，标记为 Confirmed" |

**输入**：
- 验证后的 Insight
- 验证方案
- 实践环境

**输出**：
- 验证报告
- 实践数据
- Insight 定级结果
- 改进点

**质量门控**：
- 验证是否充分？
- Insight 是否经得起实践检验？
- 是否需要更多验证？

---

### H - Harvest（收获产出）

**目标**：沉淀研究成果

**v1.x 内容**：
- 整理研究成果
- 编写最佳实践
- 制作使用指南
- 建立知识库

**v2.0 新增 — 知识交互协议**：

| 动作 | 说明 | 示例 |
|------|------|------|
| **🔑 洞见提炼子步骤** | 从本轮研究中正式提炼 Insight | "本轮研究共产出 3 个候选 Insight，2 个通过验证，正式归档" |
| **写入洞察索引** | 将正式 Insight 写入 insights_index.md | "Insight #15: [描述]，来源：[课题]，关联：[其他 Insight]" |
| **跨课题关联检查** | 检查新 Insight 对其他课题的影响 | "Insight #15 对课题 B 的 Insight #8 有补充/矛盾/增强作用" |
| **触发级联更新** | 如果影响其他课题，触发更新 | "课题 B 需要根据 Insight #15 更新其理论文档" |

**🔑 洞见提炼子步骤详解**：

```
1. 收集本轮研究的所有候选 Insight
   ↓
2. 逐一检验：能否改变行动逻辑？
   ├── 是 → 正式 Insight
   └── 否 → 降级为 Data 或 Info
   ↓
3. 对每个正式 Insight：
   ├── 编号
   ├── 写入洞察索引
   ├── 标注来源课题
   ├── 标注关联 Insight
   └── 标注适用范围
   ↓
4. 检查跨课题影响
   ├── 有影响 → 触发级联更新
   └── 无影响 → 完成归档
```

**输入**：
- 验证后的 Insight
- 验证报告
- 实践经验

**输出**：
- 研究报告
- 更新后的洞察索引
- 跨课题关联记录
- 最佳实践文档

**质量门控**：
- Insight 是否全部归档？
- 跨课题关联是否检查？
- 产出是否可复用？

---

### R - Reflect（反思迭代）

**目标**：持续优化研究方法

**v1.x 内容**：
- 反思研究过程
- 识别改进点
- 优化方法论
- 准备下一轮

**v2.0 新增 — 知识交互协议**：

| 动作 | 说明 | 示例 |
|------|------|------|
| **🔑 课题网络影响评估** | 评估本轮研究对课题网络的影响 | "本轮研究增加了 2 个跨课题连接，课题网络更紧密了" |
| **课题健康度更新** | 更新当前课题的健康度指标 | "活跃度：高；深度：Level 2；连接度：3；产出度：5 个 Insight" |
| **知识图谱更新** | 更新知识间的关系图 | "Insight #15 和 Insight #8 形成了互补关系" |
| **下一步优先级评估** | 基于课题网络状态决定下一步 | "课题 C 的连接度为零，建议下次梳理时重点关注" |

**🔑 课题网络影响评估详解**：

```
1. 本轮研究新增了什么 Insight？
   → Insight #15, #16

2. 这些 Insight 建立了哪些跨课题连接？
   → #15 连接了课题 A 和课题 C
   → #16 增强了课题 A 和课题 B 的已有连接

3. 课题网络发生了什么变化？
   → 课题 C 从"孤岛"变为"有连接"
   → 课题 A 成为"枢纽节点"

4. 需要采取什么行动？
   → 下次梳理时重点关注课题 C 的健康度
   → 考虑在课题 A 上做更多跨课题整合
```

**输入**：
- 整个研究过程
- 成果和问题
- 知识交互记录
- Human 反馈

**输出**：
- 反思笔记（reflections/）
- 课题网络影响报告
- 方法论改进
- 下一轮研究计划

**质量门控**：
- 反思是否充分？
- 课题网络影响是否评估？
- 是否发现方法论问题？

## 跨课题触发机制（v2.0 新增）

### 什么是跨课题触发？

当一个课题的研究产出影响了另一个课题的知识状态时，触发关联更新。

### 触发条件

| 触发类型 | 说明 | 动作 |
|----------|------|------|
| **补充型** | 新 Insight 补充了另一个课题的知识 | 在目标课题中标注关联 |
| **矛盾型** | 新 Insight 与另一个课题的 Insight 矛盾 | 触发冲突解决流程 |
| **增强型** | 新 Insight 为另一个课题提供了额外证据 | 增强目标 Insight 的置信度 |
| **衍生型** | 新 Insight 引发了新的研究问题 | 在目标课题中创建新的研究条目 |

### 触发流程

```
Harvest 阶段产出 Insight #15
  ↓
检查跨课题关联
  ↓
发现：Insight #15 对课题 B 的 Insight #8 有补充作用
  ↓
在课题 B 中记录：
  - "关联 Insight：来自课题 A 的 #15"
  - "影响：补充了 Insight #8 的适用范围"
  ↓
更新洞察索引中的关联关系
  ↓
下次研究课题 B 时，优先读取关联 Insight
```

## 循环使用模式

### 完整循环

**适用场景**：全新研究课题

**流程**：S → E → A → R → C → H → R → (循环)

**时间**：多个会话

### 快速循环

**适用场景**：已有研究基础

**流程**：A → R → H → R

**时间**：1-2 个会话

### 单点深入

**适用场景**：需要深入研究某个方面

**流程**：在某个阶段停留，深入探索

**时间**：根据需要

### 知识萃取循环

**适用场景**：从已有研究中萃取知识

**流程**：回顾已有产出 → 识别候选 Insight → 判定 → 归档

**时间**：1 个会话

## 质量标准

### 每个阶段的质量要求

| 阶段 | 质量标准 | 知识交互标准（v2.0 新增） |
|------|---------|--------------------------|
| Survey | 发现真实问题 | 已检索已有知识，避免重复 |
| Explore | 检索充分全面 | 已萃取新 Info，整理为 Data |
| Analyze | 理论逻辑自洽 | 已尝试 Data→Insight 提炼 |
| Review | Human 充分参与 | Insight 经 Human 验证 |
| Confirm | 验证数据充分 | Insight 经实践检验 |
| Harvest | 产出可复用 | Insight 正式归档，跨课题关联已检查 |
| Reflect | 反思深入透彻 | 课题网络影响已评估 |
