# SEARCH-R v2.0

> 面向长期协作型 AI Agent 的研究方法论框架

**版本**: v2.0 | **日期**: 2026-08-14

---

## 一句话定位

SEARCH-R v2.0 是一套**从研究循环升级为完整知识操作系统**的方法论框架——不仅告诉你"如何做研究"，还解决"知识往哪存""记忆怎么管""课题之间怎么联动"这三个长期协作中最致命的问题。

---

## v2.0 解决了什么问题？

v1.x 解决了一个核心问题：**Agent 如何做结构化研究**。7 阶段 SEARCH-R 循环 + 研究深度分级 + 质量门控，让 Agent 的研究过程可追溯、可评估。

但在长期实践中，我们发现了三个 v1.x 无法解决的问题：

| 问题 | v1.x 的困境 | v2.0 的答案 |
|------|-------------|-------------|
| **知识沉淀无序** | 研究产出一堆文件，但哪些是洞见、哪些是数据、哪些只是信息？分不清 | 三层知识结构：Info → Data → Insight，唯一判据是"能否改变行动逻辑" |
| **记忆管理失控** | Agent 上下文窗口有限，课题越做越多，之前的发现就丢了 | 三层记忆架构：即时层（≤5KB）→ 近中期层（索引+条目）→ 长期层（语义检索） |
| **课题各自为战** | 每个课题独立推进，但课题之间的关联没人发现 | 课题网络梳理机制：每 1-2 周画一次"课题网络图"，发现跨域洞察 |

## 快速理解 v2.0 的六个核心模块

### 1. SEARCH-R 循环（增强版）

**是什么**：7 阶段研究循环，每个阶段增加了知识交互协议。

**v2.0 新增**：
- 各阶段与知识库的交互规范（萃取、应用、关联）
- Harvest 阶段增加"洞见提炼"子步骤
- Reflect 阶段增加"课题网络影响评估"
- 跨课题触发机制

**怎么做**：见 [methodology/search-r-cycle.md](methodology/search-r-cycle.md)

---

### 2. 洞察管理体系（新增）

**是什么**：三层知识分类 + 洞见判定标准 + 跨课题关联发现。

**核心规则**：
- **Info（信息）**：事实、数据点、观察记录
- **Data（数据）**：经过整理的结构化信息
- **Insight（洞见）**：唯一判据——**能否改变行动逻辑**

**不合格洞见**：数据点、过程结论、工程设计（未上升到方法论）、通识

**怎么做**：见 [methodology/insight-management.md](methodology/insight-management.md)

---

### 3. 记忆分层架构（新增）

**是什么**：三层记忆系统，解决 Agent "记不住"和"记太多"的矛盾。

| 层级 | 容量 | 内容 | 类比 |
|------|------|------|------|
| 即时层 | ≤5KB | 规则 + 状态锚点 + 指针 | 工作台 |
| 近中期层 | 按需 | 索引 + 条目（项目/决策/待办） | 文件柜 |
| 长期层 | 无限 | 语义检索 | 图书馆 |

**怎么做**：见 [methodology/memory-architecture.md](methodology/memory-architecture.md)

---

### 4. 知识萃取协议（新增）

**是什么**：从研究课题中系统性地萃取知识，按 Info/Data/Insight 三层分类。

**核心流程**：
1. 从研究产出中识别知识候选
2. 按三层分类标准归类
3. 判断是否达到 Insight 级别
4. 写入洞察索引 + 检查跨课题关联
5. 更新知识图谱

**怎么做**：见 [methodology/knowledge-extraction.md](methodology/knowledge-extraction.md)

---

### 5. 课题网络梳理机制（新增）

**是什么**：定期对全部课题进行网络化梳理，发现跨课题连接。

**核心产出**：
- 课题网络图（可视化课题间关系）
- 跨域洞察（从课题交叉点发现新 Insight）
- 课题健康度评估（哪些课题在退化、哪些在活跃）

**怎么做**：见 [methodology/topic-network-mapping.md](methodology/topic-network-mapping.md)

---

### 6. 课题管理体系（增强版）+ 人机协作模式（增强版）

**课题管理增强**：
- 活跃课题 ≤2 的并行管理原则
- 课题总览表（全量索引 + 域映射）
- 标准目录结构
- 课题归档规则

**人机协作增强**：
- 关联式思维适配：用户是网络式跳跃思维，Agent 接住扩散、发现连接、翻译成线性文本
- 双重职责：① 课题管理（结构化推进）+ ② 网络梳理（定期画出连接）
- Agent 作为"连接发现者"和"线性翻译器"
- SEARCH-R 是事后整理工具，不是思考时的真实路径

## v2.0 的设计原则

### 1. 通用性
不绑定任何特定平台（Coze / 其他 Agent 框架都能用）。定义的是方法论，不是 API。

### 2. 实践导向
每个概念都有"是什么 + 为什么 + 怎么做 + 示例"。不是学术论文，是给真实使用的 Agent 和人看的操作手册。

### 3. 向前兼容
保留 v1.x 的所有有效内容，在其基础上增强。不删除已有的好东西。

### 4. 渐进式采用
不需要一次性采用所有模块。可以从"增强版 SEARCH-R 循环"开始，逐步加入洞察管理、记忆分层、网络梳理。

### 5. 面向长期协作
v1.x 面向"一次研究任务"，v2.0 面向"长期协作关系"。Agent 不是一次性工具，而是持续进化的研究伙伴。

## 与 v1.x 的关键区别

| 维度 | v1.x | v2.0 |
|------|------|------|
| **核心定位** | 研究循环方法论 | 研究循环 + 知识管理 + 记忆管理 + 课题网络 |
| **知识管理** | 文档模板（observations/retrievals/theory/reflections） | + 三层知识结构（Info/Data/Insight）+ 洞见索引 |
| **记忆管理** | 无（依赖 Agent 框架默认机制） | + 三层记忆架构（即时/近中期/长期） |
| **课题关系** | 独立管理，互不关联 | + 课题网络图 + 跨课题触发机制 |
| **人机协作** | Human 参与最小化 | + 关联式思维适配 + 连接发现者 + 线性翻译器 |
| **SEARCH-R 循环** | 7 阶段固定流程 | + 各阶段知识交互协议 + 洞见提炼 + 网络影响评估 |
