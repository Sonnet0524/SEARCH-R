# 技能进化技能
> 从静态技能到动态学习——让 Agent 技能持续改进

**版本**: v2.1 | **日期**: 2026-08-14

## 技能信息

| 属性 | 值 |
|------|-----|
| 名称 | skill-evolution |
| 类型 | 元技能（Meta-Skill） |
| 依赖 | 文件读写、技能执行记录 |
| 触发 | 技能使用后评估、定期巡检 |

---

## 概述

技能进化是一个**元技能**——它不执行具体业务，而是改进其他技能的执行方式。

**核心理念**：每个技能在使用后都应被评估是否需要进化。进化不是推倒重来，而是基于使用反馈的渐进式改进。

---

## 触发条件

### 条件 1：使用后评估（每次技能执行后）

每次技能执行完成后，进行快速评估：

```
1. 技能是否完成了预期目标？
   ├── 是 → 记录成功模式
   └── 否 → 进入条件 2

2. 失败原因是什么？
   ├── 输入不足 → 改进输入要求
   ├── 方法错误 → 改进执行流程
   ├── 外部限制 → 记录约束，等待条件变化
   └── 设计缺陷 → 触发正式进化流程
```

### 条件 2：正式进化触发（满足以下任一条件）

| 触发条件 | 说明 |
|---------|------|
| 同类错误出现 ≥3 次 | 说明不是偶发问题，是设计缺陷 |
| Human 明确反馈不好用 | 直接使用者的体验最有价值 |
| 新工具/方法可用 | 有更好的实现方式时应该升级 |
| 定期巡检发现瓶颈 | 每月一次技能健康度检查 |

## 执行流程

### 阶段 1：诊断

```
1. 收集问题证据
   - 哪些场景下技能表现不好？
   - 具体失败案例是什么？
   - 失败模式是否可重复？

2. 定位根因
   - 输入规格不够明确？
   - 执行流程有缺陷？
   - 输出格式不符合预期？
   - 依赖的工具/数据有问题？

3. 评估影响范围
   - 这个问题影响多少场景？
   - 是否有替代方案？
   - 不修复的后果是什么？
```

### 阶段 2：方案设计

```
1. 设计改进方案
   - 最小改动原则：只改必须改的部分
   - 向后兼容：不破坏已有成功案例
   - 可验证：改进后如何证明更好？

2. 评估风险
   - 改动会不会引入新问题？
   - 是否需要回滚机制？
   - Human 是否需要确认？

3. 形成改进提案
   - 改什么？为什么改？怎么改？
   - 预期效果是什么？
   - 风险如何控制？
```

### 阶段 3：验证

```
1. 小范围验证
   - 在 1-2 个简单场景中测试改进
   - 对比改进前后的效果
   - 记录是否引入新问题

2. Human 确认（如果涉及重大改动）
   - 展示改进前后的对比
   - 说明风险和收益
   - 获得 Human 批准后全量更新

3. 全量更新
   - 更新技能文件
   - 更新版本号
   - 记录进化日志
```

### 阶段 4：固化

```
1. 更新技能文档
   - 修改 SKILL.md 中的相关描述
   - 更新 references/ 中的参考资料

2. 记录进化日志
   - 写入 evolution-log.md
   - 包含：改了什么、为什么改、效果如何

3. 通知相关技能
   - 如果改进影响了其他技能的依赖关系
   - 更新相关的交叉引用
```

## 技能健康度检查

每月进行一次技能健康度检查：

### 检查清单

| 检查项 | 评估标准 | 状态 |
|--------|---------|------|
| 执行成功率 | 近 30 天成功率 > 80% | ✅ / ⚠️ / ❌ |
| Human 满意度 | 无负面反馈 | ✅ / ⚠️ / ❌ |
| 文档完整性 | SKILL.md 与实际一致 | ✅ / ⚠️ / ❌ |
| 依赖可用性 | 依赖的工具/数据可访问 | ✅ / ⚠️ / ❌ |
| 进化活跃度 | 近 3 个月有改进记录 | ✅ / ⚠️ / ❌ |

### 健康度报告

```markdown
# 技能健康度报告 [YYYY-MM]

## 概览
- 检查技能数：N
- 健康：X 个
- 需关注：Y 个
- 需进化：Z 个

## 详细评估
### [技能名称]
- 执行成功率：X%
- 近期问题：[问题描述]
- 建议：[改进建议]

## 进化建议
1. [优先级最高的改进]
2. [次优先级的改进]
```

## 实践指南

### 何时进行技能进化？

| 场景 | 动作 |
|------|------|
| 技能执行失败 | 快速评估，记录问题 |
| 同类错误累计 3 次 | 启动正式进化流程 |
| Human 反馈不好用 | 立即启动诊断 |
| 月度巡检 | 执行健康度检查 |
| 发现新工具/方法 | 评估是否可升级 |

### 常见问题

**Q: 每次技能执行后都要评估，会不会太频繁？**
A: 不需要正式评估。只是在执行失败时记录一下，积累到 3 次才启动正式流程。

**Q: 进化和重写有什么区别？**
A: 进化是渐进式改进，每次只改必要的部分；重写是推倒重来。优先选择进化。

**Q: 如果进化引入了新问题怎么办？**
A: 保留版本记录，可以回滚到上一版本。每次进化都要记录变更内容。
