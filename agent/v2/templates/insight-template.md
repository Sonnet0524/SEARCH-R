# 洞见记录模板

> 单个 Insight 的标准记录格式

**版本**: v2.0 | **日期**: 2026-08-14

---

## 模板

```markdown
### Insight #[编号]: [标题]

- **内容**：[一句话描述，不超过 50 字]
- **来源**：[课题名称] / [文档路径]
- **验证状态**：Candidate | Confirmed | Refuted
- **行动含义**：[知道这个后，什么行动会不同？]
- **适用范围**：[在什么条件下成立？]
- **关联 Insight**：[#XXX（补充/矛盾/增强/衍生）]
- **创建日期**：YYYY-MM-DD
- **最后更新**：YYYY-MM-DD
- **备注**：[可选的补充说明]
```

---

## 字段说明

| 字段 | 必填 | 说明 |
|------|------|------|
| 编号 | ✅ | 全局唯一编号，格式 #XXX |
| 标题 | ✅ | 简短描述，不超过 20 字 |
| 内容 | ✅ | 一句话描述，不超过 50 字 |
| 来源 | ✅ | 来源课题和具体文档路径 |
| 验证状态 | ✅ | Candidate / Confirmed / Refuted |
| 行动含义 | ✅ | **核心字段**：知道后什么行动会不同？ |
| 适用范围 | ✅ | 在什么条件下成立？边界在哪？ |
| 关联 Insight | ⬜ | 与其他 Insight 的关联关系 |
| 创建日期 | ✅ | 首次创建日期 |
| 最后更新 | ✅ | 最近修改日期 |
| 备注 | ⬜ | 补充说明 |

## 填写示例

### 示例 1：通过判定的 Insight

```markdown
### Insight #015: Agent 记忆系统应采用分层架构

- **内容**：Agent 的记忆应分为即时层/近中期层/长期层，而非平面化存储
- **来源**：agent-memory-research / theory/2026-08-10-memory-layers.md
- **验证状态**：Confirmed
- **行动含义**：设计 Agent 记忆系统时，必须分层而非把所有信息放入上下文
- **适用范围**：所有基于 LLM 的 Agent 系统，上下文窗口有限的场景
- **关联 Insight**：#008（补充——信息过载问题）、#003（增强——上下文管理）
- **创建日期**：2026-08-10
- **最后更新**：2026-08-12
- **备注**：经过 3 个案例验证，分层架构在可追溯性和效率之间取得平衡
```

### 示例 2：候选 Insight（待验证）

```markdown
### Insight #016: 课题优先级应按连接度排序

- **内容**：课题的优先级不应只看紧急度，应优先研究连接度高的课题
- **来源**：search-r-methodology / reflections/2026-08-14-network-review.md
- **验证状态**：Candidate
- **行动含义**：选择下一个研究课题时，优先选择能与现有课题建立更多连接的
- **适用范围**：多课题并行管理场景
- **关联 Insight**：暂无
- **创建日期**：2026-08-14
- **最后更新**：2026-08-14
- **备注**：需要在后续实践中验证
```

### 示例 3：被降格的候选

```markdown
### ~~Insight 候选~~: "GPT-4 有 1.8T 参数"

- **降级为**：Info
- **降级理由**：知道了这个参数规模，不改变任何设计决策
- **来源**：explore/gpt4-analysis.md
- **日期**：2026-08-10
```

```markdown
# 洞察索引

## 统计
- 总 Insight 数：X
- 本周期新增：Y
- Confirmed：Z
- Candidate：W
- Refuted：V
- 跨课题关联：N

## Insight 列表

### Insight #001: [标题]
...（按模板填写）

### Insight #002: [标题]
...
```
